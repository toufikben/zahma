## البدء السريع

```bash
python -m venv .venv && .venv/Scripts/activate     # Windows
pip install -e ".[dev]"

# قاعدة البيانات (PostGIS مطلوب)
zahma init-db

# الشبكة — ثقيل: شغّله في CI، لا محلياً
zahma build-network
zahma pick-corridors
zahma load-network
zahma router-stats --force

# بيانات تطوير (بلا مفاتيح)
zahma mock-fill --days 8 --segments 600
zahma rebuild-profiles

# المنتج
zahma estimate --from-lat 36.7167 --from-lon 3.1833 \
               --to-lat 36.7705 --to-lon 3.0589
zahma departure --from-lat 36.7167 --from-lon 3.1833 \
                --to-lat 36.7705 --to-lon 3.0589 --horizon 240 --step 30
```

### التوجيه — لماذا `scipy` لا `networkx`

القياس الفعلي على شبكة العاصمة:

| العملية | networkx | scipy CSR |
|---|---|---|
| بناء الرسم | 94 ث | 11 ث |
| توجيه واحد | 52 ث | **0.2 ث** |

`scipy.sparse.csgraph.dijkstra` مكتوب بلغة C. الفرق 260×، وهو ما يجعل
المنتج ممكناً: خادم واحد يخدم عشرات المستخدمين بدل عشرة خوادم.

### أولوية صنف الطريق — لماذا هي ضرورية

المسار داخل المدينة يمرّ عبر شوارع لا نقيسها (الحصص لا تكفي). بلا أولوية
الصنف يرجع كل مقطع غير مقيس إلى السرعة الحرة — **ثابتة لا تعرف الساعة** —
فيصبح منحنى الانطلاق خطاً مستقيماً.

جدول `class_profiles` ينقل سلوك الصنف الزمني من المقاطع المقيسة إلى غير
المقيسة. النتيجة: المنحنى يميّز بين 07:30 و11:30.

**سلسلة التراجع (لا تُعكس):** حي (0.9) ← ملف تعريف (0.6) ← صنف (0.35) ← حر (0.3).
